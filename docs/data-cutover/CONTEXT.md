# 数据割接

本语境描述旧系统重写中的数据割接及其约束。

## Language

**数据割接（Data Cutover）**：
在旧系统重写中，将权威数据按已确认的新数据形态与概念模型转换并切换至新系统的受控变更。其范围不包括普通数据库结构变更、一次性数据清洗和可逆回填。
_Avoid_：数据库迁移、数据搬运

**目标模型（Target Model）**：
新系统采用的概念、关系、约束与数据形态。割接工作区绑定当前已确认版本；割接证据可以推动有权来源更新模型，随后同一工作区推进模型基线并重新检查受影响的映射与证据。
_Avoid_：目标表结构、迁移后模型

**模型发现（Model Finding）**：
割接证据表明当前目标模型不能表达已确认业务需求或约束的发现。它触发目标模型的决策流程，但不自行改变模型，也不授权用兼容设计绕过缺口。
_Avoid_：迁移特例、兼容需求

**历史能力（Historical Capability）**：
新系统按业务要求表达或查询事实发生时状态的能力。目标模型决定是否需要及如何实现；割接验证已选语义，不预设拉链表、快照表或业务表冗余。
_Avoid_：快照数据、历史快照

**决策记录（Decision Record）**：
解决割接中业务歧义的可追溯记录，包含决定、依据、适用范围和责任主体，并绑定目标模型版本与源数据批次。基于已有证据的新决定可以推动当前批次重跑，新增或修改源证据则形成新批次；记录载体由工作环境决定，不以客户签字或固定审批流程为前提。
_Avoid_：客户签字、例外审批单

**割接契约（Cutover Contract）**：
在一个割接工作区内，关联割接范围、目标模型、源数据批次、映射决定、恢复边界和证据边界的版本化记录。它随当前批次的工作推进而更新，不是审批模板或完成证明。
_Avoid_：迁移方案、验收报告

**遗留概念处置（Legacy Concept Disposition）**：
旧系统业务概念在目标模型下的明确归宿：迁入、退役或仅作证据。物理字段只有在承载有效业务含义时才进入映射，不因旧结构存在而产生兼容设计。
_Avoid_：逐列搬迁、兼容映射

**割接结果（Cutover Outcome）**：
待迁移源数据行在当前规则下互斥且守恒的归宿：迁入、隔离或退役。无法可靠读取或验证源数据批次时阻断整批，不以失败行或 warning 补齐守恒。
_Avoid_：忽略、失败行

**割接对账（Cutover Reconciliation）**：
先证明源数据满足“读取 = 迁入 + 隔离 + 退役”，再按已声明的映射关系双向比较预期目标与实际结果。金额、期间、组织等附加维度仅由目标模型中的业务不变量触发。
_Avoid_：金额对账、行数相等

**割接产物（Cutover Artifact）**：
由特定源数据批次、目标模型基线和割接规则生成的可迭代结果。产物存在只表示已经生成，不表示允许执行或割接完成。
_Avoid_：正式产物、最终版

**身份匹配规则（Identity Matching Rule）**：
将源实体绑定到目标身份的确定性规则。规则优先使用稳定标识；采用可变或展示字段时须有决策记录和量化证据，不能唯一消除冲突的来源进入隔离。
_Avoid_：姓名匹配、字段优先级猜测

**迁移账本（Migration Ledger）**：
在换键、合并、拆分、去重或多源汇聚后记录源行与目标行关系的追溯数据。源键能够直接确定目标行时不另建账本。
_Avoid_：全量逐行副本

**割接工作区（Cutover Workspace）**：
将一个源数据批次按当前目标模型进行分析、转换和验证的隔离工作环境。工作区内的判断和证据只适用于它所绑定的源数据批次与目标模型版本。
_Avoid_：临时目录、最终版目录

**权威切换（Authority Cutover）**：
新系统在领域边界内取代旧系统，成为唯一运行时数据权威的事件。未迁入的数据进入受控隔离、整改或只读归档，不构成业务逻辑回查旧系统的依据。
_Avoid_：逐行切换、新旧双轨

**目标环境（Target Environment）**：
割接产物需要适配的数据库及其兼容模式。测试环境跑通只证明当前产物可用于测试；设计须排除与已知生产目标明显不兼容的内容，生产执行要求可在现有产物上继续收敛。
_Avoid_：生产等价测试环境

**恢复边界（Recovery Boundary）**：
割接会删除、覆盖或退役的数据范围，以及对应的恢复方法和可用恢复点。恢复机制按实际破坏范围确定，不以单事务、故障注入或固定备份方式为前提。
_Avoid_：通用回滚脚本

**证据边界（Evidence Boundary）**：
区分当前源数据批次和目标模型版本下已经证明与尚未证明事项的版本化记录。模型基线推进只使受影响的证明失效；触及身份模型、权威切换、行数守恒或恢复边界时，整批证明重新打开。
_Avoid_：就绪标志、完成证明

**源数据批次（Source Batch）**：
由一个割接工作区锁定的一组不可变源数据快照。任一快照变化都会形成新的源数据批次，原批次的割接证据不再适用。
_Avoid_：最新数据、可更新快照

**源数据清单（Source Manifest）**：
描述各项源数据的逻辑身份、结构和内容特征，并可由机器复核的清单。完整清单的批次指纹标识一个源数据批次。
_Avoid_：文件列表、人工盘点表

**进展交接（Progress Handoff）**：
源数据批次变化时，对原工作区已完成工作、未决事项、决策和证据的收束记录。它允许后续工作继承可复用判断，但不使旧证据对新批次继续有效。
_Avoid_：续跑、覆盖更新
