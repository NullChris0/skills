# NESMA FPA

本语境描述 `estimate-with-nesma` Skill 从外部知识材料中筛选可执行知识和执行功能点计数的方式。

## Language

**确定知识（Confirmed Knowledge）**：
来源基线中作为确定结论陈述的知识；不包括标记为延伸、推论、待核验或待澄清的内容。勘误与辨析仅在给出明确采用口径时属于确定知识，案例不能反向建立规则。
_Avoid_：全部来源材料、候选知识

**计数就绪度（Counting Readiness）**：
输入材料对概要 FPA 或详细 FPA 所需证据的满足程度；不包含预估 FPA。
_Avoid_：文档完成度、需求篇幅

**估算启动访谈（Estimation Intake Interview）**：
`estimate-with-nesma` 在证据审查前按需进行的逐项确认过程；Agent 先从当前 prompt、对话、交接材料和仓库事实归集启动参数，再只就缺失、歧义或必须由用户决定的内容一次询问一项，并在用户确认完整参数集后开始估算。
_Avoid_：静默采用推断、一次性参数表、正式计数

**估算启动参数集（Estimation Intake Parameters）**：
开始证据审查前必须齐备且无歧义的参数集合；其完整性取决于内容，不取决于参数来自当前 prompt、对话、临时交接材料还是可验证的仓库事实。
_Avoid_：必须使用 handoff、每次重新询问全部参数、把参数载体当成计数证据

**启动发现（Intake Discovery）**：
估算启动确认前为拟定参数而进行的浅层只读检查，仅覆盖 Agent 规则、领域上下文、ADR、issue 或规格入口、Git 状态和目录结构；不识别或分类功能，不计算功能点，也不运行应用、测试、数据库查询、浏览器或远程接口。
_Avoid_：正式证据审查、运行态采集、确认前计数

**估算启动确认（Estimation Start Confirmation）**：
估算启动访谈的结束门槛；Agent 汇总计数对象与版本时点、用户、计数范围、应用边界、计数类型、方法、证据基线、只读授权边界和输出目录，用户明确确认后才进入证据审查。
_Avoid_：默认同意、边访谈边正式计数、仅确认部分参数

**启动参数失效（Intake Invalidation）**：
正式证据审查发现事实会改变已确认的计数对象、范围、应用边界、计数类型或方法时，本次启动确认失效。当前 session 可以继续逐项讨论并形成新的完整参数，但不生成估算审阅包，也不恢复正式计数；参数完整后由用户开启新 session 重新启动估算。
_Avoid_：在原 session 内续跑、把参数矛盾当普通证据缺口、为无效参数生成阻断包

**计数对象（Counting Subject）**：
在明确版本时点上接受功能规模度量的功能集合，可以是现有应用功能存量、目标应用功能存量或本次新建/增强项目功能范围。
_Avoid_：输入材料集合、整个系统、全部需求

**计数阻断（Counting Block）**：
输入证据不足、普通计数事实无法确认或事实回答与证据冲突时，停止形成所选方法的正式估算结果，并明确指出缺失或冲突证据；只有会改变启动参数的矛盾改按“启动参数失效”处理。
_Avoid_：估算失败、静默假设、反复追问未决事实

**证据角色（Evidence Role）**：
输入材料在计数判断中承担的语义角色，分为意图、现状、规格、实现和验证；同一材料可以承担多个角色，其权威性取决于计数对象。
_Avoid_：文件类型、固定输入套餐

**证据冲突（Evidence Conflict）**：
不同证据对同一功能事实给出不一致陈述，且不能由计数对象或版本时点解释的状态。
_Avoid_：自动采用较新文件、静默选边

**只读证据采集（Read-only Evidence Collection）**：
在用户明确指定和授权的范围内检查代码、数据结构、日志、接口或运行界面，并通过不改变目标状态的实测形成计数证据。
_Avoid_：替用户编写伪 PRD、生产写入、未授权探测

**证据访问授权（Evidence Access Authorization）**：
用户在当前估算 session 中对证据读取范围和必要外部访问作出的运行许可；它控制 Agent 可以检查哪些来源，但不作为计数证据，也不写入交接材料或估算审阅包。
_Avoid_：持久授权记录、把授权当作业务事实、跨 session 默认继承

**无状态读取（State-neutral Read）**：
能够证明不会改变业务数据、会话、任务、缓存或其他生产状态的证据采集操作；业务名称含“查询”不构成无状态证明。
_Avoid_：只看 HTTP 方法、默认信任查询操作

**派生材料（Derived Material）**：
由 AI、人工转述或整理过程根据其他材料生成的文档；不可追溯的派生材料只能发现候选功能，不能独立支撑正式计数，经有权人员明确确认的条目可成为意图证据。
_Avoid_：原始证据、独立佐证

**计数主张（Counting Claim）**：
形成计数结果所依赖的单项可审查判断，例如功能存在、用户可识别性、维护责任、基本过程、功能类型或复杂度要素；其证据充分性独立于输入文件的数量和格式。
_Avoid_：整份文档可信、文件数量评分

**证据记录（Evidence Record）**：
带稳定编号的脱敏来源登记，记录证据角色、版本或实测时间、具体定位、观察事实及其支持的计数主张；正式计数项必须引用足以支持它的证据记录。
_Avoid_：复制生产数据、无定位来源说明

**计数模型（Count Model）**：
保存在 `功能点计数证据.xlsx` 中的结构化计数事实、判断和复核状态，是估算审阅包内部的权威记录。
_Avoid_：三个产物各自维护、Markdown 汇总

**可读投影（Readable Projection）**：
根据计数模型和证据来源生成的 `估算审阅报告.md` 与 `规范化功能清单.md`；其修改不会静默反向覆盖计数模型。
_Avoid_：独立事实来源、可直接覆盖工作簿的副本

**来源不可变（Source Immutability）**：
估算会话只读取输入材料并写入审阅包目录，不修改 PRD、SPEC、代码、测试、数据库或其他来源；任何回填都属于后续独立任务。
_Avoid_：边估算边改需求、自动修复输入

**Git 证据基线（Git Evidence Baseline）**：
纳入证据范围的 Git 仓库及相关 submodule 必须具有干净工作树，并以启动确认时的 HEAD commit 定位；正式证据审查结束前，任何 HEAD、工作树或 submodule 状态变化都构成计数阻断，Skill 不自动追随变化，也不替用户整理或提交。
_Avoid_：未提交快照、自动提交输入仓库、并发修改、自动切换新 HEAD

**证据审查（Evidence Review）**：
正式计数之前对输入材料、只读采集结果、证据冲突和计数就绪度进行检查的阶段。
_Avoid_：预估 FPA、直接填表

**正式计数（Formal Count）**：
证据审查达到相应方法门槛后执行概要或详细 FPA，并生成估算审阅包的阶段。
_Avoid_：客户终稿、无证据试算

**输入事实复核（Input Fact Review）**：
由熟悉业务的用户确认业务含义、功能完整性、维护责任和计数假设是否符合真实需求。
_Avoid_：公式校验、方法认证

**方法复核（Method Review）**：
由具备 NESMA/FPA 能力的审阅者确认边界、基本过程、功能分类、复杂度和公式转换是否符合方法规则。
_Avoid_：业务需求确认、自动认证

**估算审阅包（Estimation Review Package）**：
Skill 提交给用户审阅的中文命名产物集合，包含估算判断、可回填需求文档的规范化功能清单，以及逐项计数证据；它不是未经审阅即可对客户交付的终稿。
_Avoid_：客户交稿、单一估算报告

**未完成审阅包（Blocked Review Package）**：
计数阻断时生成的估算审阅包，保留已取得的证据、候选功能和缺口，但不形成正式功能点总数，未决项不进入汇总。
_Avoid_：正式估算结果、失败后空输出

**非计数需求（Non-counted Requirement）**：
证据审查中识别、但不纳入 NESMA 功能点汇总的非功能需求、质量约束、技术任务或其他排除项；规范化功能清单保留其内容及排除理由。
_Avoid_：无价值需求、静默删除
