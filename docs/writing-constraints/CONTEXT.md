# Writing Constraints

本语境描述个人写作 Skill 如何约束信息承诺与常见的模型化表达。

## Language

**有据中文写作（Grounded Chinese Writing）**：
面向客户文档、个人技术笔记与技术博客的新写和保真改稿能力。它以信息约束为主，以少量表达校验为辅。
_Avoid_：活人感写作、中文文风

**信息约束（Information Constraint）**：
确保事实、推断、决策与未知保持各自身份的硬规则。材料不足时降低文档承诺，不补造信息。

**主张覆盖（Claim Coverage）**：
每个实质性主张都有相称的材料或明确的推断标识。覆盖程度按主张判断，不按篇幅或材料数量计算。
_Avoid_：五件材料、材料配额

**材料冲突（Source Conflict）**：
两份或以上材料对会影响结论的事项给出不兼容信息。Agent 保留冲突并暴露其影响，不自行选择有利版本；用户裁决记为决策。

**权威来源（Authoritative Source）**：
对特定主张具有直接认定能力的来源。用户或客户可认定自身需求与决策；官方文档、一手材料或实际系统可认定相应外部事实。

**真实案例（Observed Case）**：
有可追溯来源、可以支撑问题或需求确实存在的已发生情况。

**构造示例（Constructed Example）**：
明确标注为示例或假设、且符合已知规则的未发生场景。它只解释规则或流程，不证明需求存在。
_Avoid_：真实可能发生的情况、来源不明的客户案例

**承诺降级（Commitment Downgrade）**：
材料不足时采用的失败策略。正式文档标明待确认项或决策缺口；技术文章先研究，仍不足时缩小论题或降低结论强度。

**完整交付（Complete Delivery）**：
成稿覆盖用户要求的完整范围。关键缺口尚未解决时先检索或集中追问，不把已完成章节与待写章节拼成半成品交付。
_Avoid_：部分交付

**表达校验（Expression Check）**：
针对常见模型化中文表达的语境化提醒，不是统一文风或绝对禁令。
_Avoid_：去 AI 味硬规则、文风规则

**虚构对立（Manufactured Contrast）**：
先否定一个说法，再通过推翻它引出判断或设计取舍。仅在纠正上下文中已经出现的具体误解，或区分会改变读者行动的边界时使用对比；其他情况直接写选择、原因与代价。
_Avoid_：翻案句式

**解释类比（Explanatory Analogy）**：
用熟悉事物解释技术对象或关系，并保留两者的边界。类比可以辅助理解，不能代替事实或机制。

**拟人化（Personification）**：
把人的意图、情绪或动作赋予抽象概念的表达。成稿不使用拟人化。

**空路标（Empty Signpost）**：
只宣告“这里重要”或“下面更深入”，却没有增加实际信息的过渡表达。表达校验同时检查其语义与已确定的固定短语。

**既定措辞（Established Wording）**：
来自客户原话、组织术语或用户明确要求保留的表达。即使措辞抽象，也不由 Agent 擅自替换；含义影响文档时请求确认。

**保真改稿（Fidelity-preserving Revision）**：
在用户指定范围内修改表达，同时保留作者立场、事实承诺、既定术语与未授权调整的结构。信息缺口可以标注，不借润色补写或改写事实。

**信息推进（Information Progression）**：
段落相对上下文新增事实、推理步骤或行动价值。摘要、风险重述与跨章节引用等具有文档功能的重复不视为停滞。

**结论作用域（Conclusion Scope）**：
结尾可以收束正文已经建立的事实、决策、风险、行动或影响，不扩张到正文未处理的时代性或普遍性判断。

**可定位主干（Locatable Core）**：
句子的责任主体与实际动作易于找到。仅在条件、定语或名词化结构遮蔽主干时重写，不强制统一语序。

**具体动作（Concrete Action）**：
写明动作的对象、变化或验证方式。专业术语可以保留；无法说明实际变化的“优化、提升、赋能”等空泛动作需要补实。

**术语一致性（Terminology Consistency）**：
同一概念在一份文档中使用同一名称。只有概念本身不同才更换术语，不为追求文采轮换近义词。

**任务参考（Task Reference）**：
仅在当前写作任务命中对应分支时读取的 `references/` 文档，用于承载不同文档类型的专属规则。

**正式文档（Formal Document）**：
用于评审、决策、实施或交付的 PRD、Spec、说明书等文档，无论读者来自客户还是内部团队。
_Avoid_：客户文档

**技术文章（Technical Prose）**：
用于个人记录、解释或公开分享的技术笔记与技术博客。
