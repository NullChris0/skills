# 估算启动访谈

在证据审查前完成本访谈。从当前 prompt、对话、可选交接或重启文本和可验证的仓库事实归集参数；参数是否齐备取决于内容，而非载体。交接和重启文本都不是证据。

## 启动发现

确认前只读 Agent 规则、领域上下文和 ADR、issue 或规格入口、Git 状态及目录结构。不识别或分类功能，不计数，不运行应用、测试、数据库查询、浏览器或远程接口。

若缺少项目或证据上下文，先只询问项目或材料入口。否则按以下依赖顺序处理缺失、歧义和必须由用户决定的参数，每轮只问一个决定：

1. 项目或证据入口。
2. 计数对象和业务版本时点。
3. 计数类型：`application`、`new` 或 `enhancement`。
4. 纳入和排除的计数范围。
5. 功能用户。
6. 应用边界和相关数据维护责任。
7. FPA 方法：`overview` 或 `detailed`。
8. 证据范围及本 session 的必要外部只读访问授权。
9. 输出目录。

已齐备且无歧义的参数直接跳过。可根据证据拟定对象、范围、用户、边界、证据来源和输出路径供用户确认或修改，但不将草案称为“推荐”。计数类型和 FPA 方法必须由用户选择，不推荐、默认或静默降级；本 Skill 不支持预估 FPA。用户、计数范围、应用边界及相关维护责任需要明确同意，“你来判断”不构成确认。

用户对当前决定表示“不知道”、“解释一下”或同等意思时，进入 `Chat about this`：说明各选项、现有证据、证据门槛和后果，不直接或附条件地建议某个选项，然后回到同一个待决定项。

输出目录必填。优先从目标仓库规则推断，否则使用 `./NESMA估算/<计数对象名称>/`。目录非空时拟定新版本目录，永不覆盖。

## 启动确认

所有参数齐备后，在单独一轮显示一份紧凑的完整摘要：

- 计数对象和业务版本时点；
- 计数类型和 FPA 方法；
- 功能用户和应用边界；
- 纳入与排除范围；
- 证据仓库和其他来源；
- 外部只读访问范围；
- 输出目录。

该轮到此停止；即使原始 prompt 已完整或要求直接开始，也等待下一条用户消息。只有对最新完整摘要的无条件肯定答复才启动证据审查。修正、条件、歧义或参数变更使上次确认失效；更新后在后续的单独一轮再次显示完整摘要。

证据访问授权只在当前 session 有效，不写入交接、领域文档或审阅包；只记录实际获取且已脱敏的证据来源。新 session 重新验证 Git 事实并重新获得外部访问授权。访谈取消时不写任何产物，也不自动创建交接。

## 确认后

收到启动确认时，固定所有 Git 证据仓库的干净 HEAD、工作树和 submodule 状态。证据审查完成前，任一状态变化均构成计数阻断；不跟随新 HEAD，不判断变化是否相关。

启动后的普通输入事实问题仍每轮只问一项。逻辑文件拆合、基本过程同一性、事务引用的逻辑文件、跨边界 DET 有无、以及 EO/EQ 分叉留到证据审查后的 [计数判别访谈.md](计数判别访谈.md)，不在启动后提前问完。用户无法回答普通输入事实或回答与证据冲突时，生成未完成的三件套审阅包。

若证据使已确认的计数对象、范围、边界、计数类型或方法失效，本 session 不生成审阅包、不恢复计数。每轮讨论一个替换决定；新参数齐备后，输出一份包含具体参数的可复制重启 prompt，要求用户在新 session 启动。重启 prompt 可带证据来源和上次已确认判别作草案，不带上一 session 的访问授权，并要求重新授权。新 session 仍须经过启动确认，并重新完成计数判别访谈。
