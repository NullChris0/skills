# 复核与输出

## 临时输入

向生成器提供 UTF-8 JSON，顶层字段为：`subject`、`method` (`overview|detailed`)、`count_type` (`application|new|enhancement`)、`package_version`、`user`、`scope`、`boundary`、`evidence`、`data_functions`、`transactions`、`non_counted`、`assumptions`、`confirmed_discriminations`；增强应用净变化另传 `baseline_ufp, baseline_evidence_ids`。首版 `package_version` 为 1，重跑修订时递增。

证据项使用 `id, role, source, version, location, fact, claims, traceable`，派生材料标 `derived`，冲突写 `conflict`。功能项使用 `id, name, type, change, evidence_ids`；详细新增/修改数据项加 `ret, det, rets, dets, detail_evidence_ids`，详细新增/修改事务项加 `det, ftr, dets, ftrs, processing, detail_evidence_ids`。`rets`/`dets`（数据）与 `ftrs` 为命名字符串清单；事务 `dets` 为 `{name, side}`，`side` 只能是 `输入`、`输出`、`启动触发` 或 `消息`；`ftrs` 引用数据功能编号。详表条数必须等于对应整数，启动触发和消息各至多一行，启动触发行名称必须是「启动触发」，消息行名称必须是「消息」，FTR 必须引用已登记数据功能，否则计数阻断。`confirmed_discriminations` 为已确认判别的字符串清单，投影到「假设与冲突」且状态为已确认。增强项目的删除项必须加 `before_fp, before_evidence_ids`；修改项只在输出应用净变化时提供这两个字段。删除功能不要求不存在的变更后复杂度证据。临时 JSON 不进入审阅包。

## 产物

只交付 `估算审阅报告.md`、`规范化功能清单.md`、`功能点计数证据.xlsx`。工作簿是结构化计数模型权威；Markdown 是可读投影。工作簿固定包含：`计数说明`、`证据登记`、`数据功能`、`数据功能详表`、`事务功能`、`事务功能详表`、`假设与冲突`、`汇总`、`复核记录`。详表各行一个元素；规范化功能清单不展开详表。

审阅者只编辑黄色解锁字段；公式和计数事实受保护。区分规则/公式检查、输入事实复核、NESMA/FPA 方法复核。任何修改都创建新版本目录并从证据及明确接受的反馈重跑；Schema 或 Generator 版本不同则严格不兼容，不迁移旧包。

阻断包仍生成三件套，但不显示正式总数，未决行不进入公式。首版状态只能是 `计数阻断` 或 `待复核`。
