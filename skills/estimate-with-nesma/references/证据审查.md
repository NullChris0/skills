# 证据审查

## 输入档案

- 普通需求：意图（目标、范围、变更授权）+ 规格（PRD、用例、验收准则）+ 可选实现/验证证据。
- 遗留重写：意图 + 现状（现行流程、用户资料）+ 实现（代码、数据模型、接口）+ 验证（测试、运行观察）+ 目标规格。

输入按意图、现状、规格、实现、验证五种证据角色登记；文件格式不产生单独流程，同一来源可承担多个角色。派生材料须追溯原始来源；不可追溯的派生 PRD 只能发现候选功能，不能独立支撑正式计数。

## 审查门槛

先确认用户、计数范围、应用边界、计数对象和版本时点；任一缺失均阻断概要与详细 FPA。记录每条证据的稳定编号、角色、版本或实测时间、具体定位、观察事实和所支持主张。

冲突不能按文件日期自动解决。将冲突关联的功能行排除于公式，直到有权来源解释或确认。正式行必须具有支持功能存在、用户可识别性、维护责任、基本过程、类型及所选方法复杂度要素的可定位证据。

Git 来源须在启动确认时以干净的工作树、HEAD commit 及 submodule 状态固定；审查完成前任一状态变化均构成计数阻断。生产采集须由用户在当前 session 明确授权，并证明读取不改变业务数据、会话、任务、缓存或其他状态；否则不执行并登记缺口。整个会话只写输出目录。
