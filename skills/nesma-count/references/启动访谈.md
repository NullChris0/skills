# 启动访谈

先用当前 prompt、交接材料和可验证的仓库事实归集参数，再把仍缺失或必须由用户决定的内容合并成一次启动确认。不要逐项打断用户。

## 浅层只读侦察

确认前只读以下内容：

- Agent 规则和项目领域索引；
- 相关 `CONTEXT.md`、ADR、issue 或规格入口；
- 目录结构、Git 状态、tag 和提交；
- 用户提供的输出目录和模板路径。

此时不识别功能、不分类、不计数，不运行应用、测试、数据库查询、浏览器或远程接口。

## 一次确认

能查到的事实直接填好。仍缺失或需要用户拍板的内容一次列出，用户可在一条消息内回答：

1. 计数对象名称和业务版本时点。
2. 项目入口：后端、前端、脚本、数据工程等全部只读仓库。
3. 每个仓库的固定 commit、tag 或交付分支；tag 和分支必须解析为 commit，不默认使用当前工作区。
4. 项目领域文档和交付边界入口。
5. 计数类型：`新项目` 或 `存量应用`；当前契约不支持增强项目。
6. FPA 方法：`NESMA 详细 FPA` 或 `NESMA 概要 FPA`。详细方法需要 RET/DET 与带侧 DET/FTR；概要方法需要已识别的数据功能和事务功能。
7. 功能用户、应用边界、纳入范围和明确排除范围。
8. 证据范围，以及本 session 是否授权现网、数据库、浏览器或远程接口的只读访问。
9. 新输出目录；目录必须不存在或为空。
10. 已提供的计数模型、功能清单、规格或数据字典路径；没有就写“无”。

用户确认后，固定所有 Git 证据仓库的提交和工作树状态。确认后若发现会改变计数对象、范围、边界、类型或方法的矛盾，停止本轮计数，更新参数后重新确认。

## 确认后的边界

- 只写新输出目录，不修改被估仓库。
- 发现的功能候选和证据先进入内部清单；证据不足的分叉批量问用户。
- 用户确认记录写入证据清单，不写成假设。
- 用户无法确认的项目明确排除，不进入 UFP。
