# 复核与输出

## 计数模型 JSON

顶层字段固定为：

- `schema_version`：整数；
- `package`：`name`、`version`、`output_directory`、`status`；
- `baseline`：后端/前端的 commit、tag 或 ref；
- `counting`：`project_type`、`method`、`change_type`、`users`、`application_boundary`、`scope`；
- `confirmed_decisions`：字符串列表；
- `data_functions`：数据功能行；
- `transactions`：事务功能行；
- `evidence`：证据清单；
- `excluded`：已排除项。

数据功能行至少包含：

`id`、`module`、`name`、`type`、`rets`、`dets`、`evidence`、`confirmation`。

详细 FPA 的 `rets` 和 `dets` 是命名字符串列表。`ret_count`、`det_count`、`complexity`、`fp` 可由生成器计算；若 JSON 中已有，必须与计算结果一致。

事务功能行至少包含：

`id`、`module`、`name`、`type`、`dets`、`ftrs`、`processing`、`evidence`、`confirmation`。

事务 `dets` 是 `{name, side}` 列表，`side` 只能是 `输入`、`输出`、`启动触发`、`消息`；启动触发和消息各至多一行，名称分别是 `启动触发` 和 `消息`。`ftrs` 必须引用已登记的数据功能编号。

证据项至少包含：

`id`、`role`、`source`、`version`、`location`、`fact`、`supports`、`status`。

`excluded` 项至少包含 `item`、`reason`，可有 `impact` 和 `evidence`。

不得出现 `assumptions`、`unresolved`、未确认的正式行或无法追溯的证据引用。

## 生成

在新输出目录运行：

```bash
python <skill-directory>/scripts/generate_count_package.py <model.json> <output-dir>
```

生成器只写：

- `计数模型.json`
- `功能点计数证据.xlsx`

输出目录必须为空或不存在；生成器不会覆盖旧包，也不会写 Markdown 报告、Word、PDF 或其他交付件。

## 四张表

1. `汇总`：对象、版本、基线、计数类型和方法、用户、边界、范围、ILF/ELF/EI/EO/EQ 数量、数据/事务 FP、UFP、排除项、证据覆盖率、完成状态。
2. `数据功能`：编号、模块、名称、类型、RET/DET 数、复杂度、FP、RET/DET 明细、证据、用户确认。
3. `事务功能`：编号、模块、名称、类型、DET/FTR 数、复杂度、FP、处理说明、带侧 DET 明细、FTR 引用、证据、用户确认。
4. `证据清单`：编号、角色、来源、版本/commit/时间、精确定位、观察事实、支持条目、状态、排除理由。

## 完成校验

- 四张表存在且没有额外工作表；
- 数据功能、事务功能和证据编号唯一；
- RET/DET/FTR 数与明细条数一致；
- 每个 FTR 引用已登记的数据功能；
- 每个正式行有有效证据和用户确认；
- 汇总数可由明细复算；
- 最终 JSON 不含假设或未决项。
