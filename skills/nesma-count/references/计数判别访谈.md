# 计数判别访谈

在证据审查后、写入计数模型前，把仍有一种以上合法读法的分叉集中处理。

## 批量提问

每轮一次列出全部高影响分叉，不再逐题打断用户。每项包含：

- 证据编号和具体定位；
- 已观察到的事实；
- 一种以上合法读法；
- 每种读法对数据功能、事务类型或 UFP 的影响；
- agent 建议的默认口径、理由和不确定性；建议不是事实，必须由用户确认或修改。

NESMA 已定死的复杂度、权重和计数机制不问用户。只问需要业务知识或范围授权的判断。

## 必问类

- 逻辑文件拆合：独立 ILF/ELF，还是已有文件的 RET；
- 基本过程同一性：一组用户动作是一个还是多个基本过程；
- 事务读取或维护哪些逻辑文件；
- 跨边界、用户可识别且不重复的 DET；
- 是否包含计算、派生、维护 ILF 或改变行为，以区分 EO/EQ；
- 新建、存量或排除范围中会影响计数对象的业务边界。

## 确认与记录

用户答复后，生成一份只含本轮问题和答复的确认摘要。用户确认后：

- 把答复写成证据清单中的“用户确认”记录；
- 更新候选行或排除项；
- 不把答复写进 Skill 或领域文档，除非用户另行要求。

用户无法回答的项目保持未决，继续询问其余分叉；全部问完后，将未决项写入 `excluded` 并从正式计数中排除。最终 JSON 不保留 `assumptions` 或 `unresolved`。
