# 交付模型契约

阶段二可以保留一个内部 `delivery-model.json`，把阶段一 JSON、代码证据、接口 YAML、图片和 Word 章节连接起来。该文件不是客户输入，也不是第二套计数事实。

## 顶层

```json
{
  "model": {},
  "specs": [],
  "dbs": [],
  "masters": [],
  "features": [],
  "mappings": [],
  "document": {}
}
```

- `model`：阶段一计数模型的只读副本或引用。
- `specs`：HTTP 接口和跨边界只读契约。
- `dbs`：物理表补充信息。
- `masters`：边界外主数据读取契约。
- `features`：功能清单行。
- `mappings`：NESMA 覆盖映射。
- `document`：Word 章节、段落、表格、图片和图题。

## 文档

`document` 至少包含：

- `title`、`subtitle`、`version`、`date`；
- `counts`：从阶段一 JSON 复算的 ILF/ELF/EI/EO/EQ/UFP，不手工填写；
- `sections`：按顺序排列的章节；
- `cover`、`header`、`footer` 等样式字段。

章节项至少包含：

```json
{
  "heading": "章节标题",
  "level": 2,
  "paras": ["正文"],
  "images": [{"path": "接口表/images/card.png", "caption": "表号 图题"}],
  "tables": [{"headers": [], "rows": [], "widths": []}]
}
```

上面的标题、图题和表号是形状示例。实际章节写在本次 `sections` 里，不套用标准需求大纲。所有图片路径使用相对交付目录的路径，不能引用 `/tmp` 或旧接口表目录。所有 NESMA 编号和 UFP 从阶段一 JSON 派生。

`card_style` 可选，指向改写后的 `api-card.sty`。相对路径相对交付模型所在目录。缺省时使用 Skill 自带范本。

## 映射

每条映射至少包含：

```json
{
  "nesma": "TF-01",
  "type": "EI",
  "name": "功能名称",
  "fp": 3,
  "feature": "功能清单序号或行标识",
  "section": "正文章节/页面/数据模型",
  "interface": "YAML id 或空",
  "status": "已覆盖"
}
```

映射必须覆盖阶段一 JSON 的全部正式行；没有接口的功能保留空 `interface`，不能为了填满表格虚构接口。

## 生成顺序

1. 读取阶段一 JSON，校验无假设和未决项；
2. 生成映射；
3. 从代码证据生成接口 YAML；
4. 渲染卡片图片；
5. 生成功能清单 XLSX；
6. 生成 `delivery-model.json`；
7. 生成 DOCX；
8. 执行独立校验脚本。
