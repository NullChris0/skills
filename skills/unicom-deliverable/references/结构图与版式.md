# 结构图与版式

## 系统总体功能结构图

客户范例的 1.2 节有一张分块式结构图。用 `build_structure_diagram.py` 从 JSON 生成 draw.io 源文件，再用 `drawio -x -f png -s 2` 导出。源文件和导出图放在用户指定的目录（通常是该系统的截图目录），文件名 `系统总体功能结构.drawio` / `.png`。

```json
{"title": "纪检新闻系统",
 "left": [{"title": "主系统<br>（大额成本系统）", "items": ["统一登录", "权限控制", "人员信息"]}],
 "rows": [
  [{"title": "公开门户", "cols": 2, "items": ["首页展示", "栏目文章列表", "附件下载"]},
   {"title": "新闻文章管理", "cols": 3, "items": ["文章增删改查", "提交审核", "审核通过与驳回"]}],
  [{"title": "数据存储", "cols": 4, "items": ["新闻栏目", "新闻文章"]},
   {"title": "外部资源", "cols": 2, "items": [["对象存储", "exist"]]}]]}
```

- `left` 是外部系统栏，条目一律按“已有能力”着色。
- `rows` 的每一行是若干并排的模块框，`cols` 是框内每行的方块数。一行里各框的 `cols` 之和不要超过 8。
- 条目写成 `["名称", "exist"]` 时按“已有能力”着色，否则是“本次新增”。
- 最后一行放数据存储（取清单里的数据实体）和外部资源。

画之前问用户三件事，各给出推荐项：

1. 版式：分块式（与范例一致，推荐）还是树状图。
2. 方块粒度：一条功能一个方块，还是每个模块合并成 3 到 6 个概括方块（如“文章增删改查”“审核通过与驳回”）。
3. 颜色：按“本次新增 / 已有能力”着色并放图例（推荐），还是按模块着色。

导出后看图：文字不得溢出方块，各行宽度对齐。图宽 1300 像素，放进 Word 版心后方块文字约 6 磅；方块超过 60 个时提醒用户字会偏小。

## Word 版式

`assets/需求说明书版式模板.docx` 取自一份验收通过的交付件，只保留带 `{{名称}}` 标记的原型段落：封面三行、目录、四级标题、三种正文段、两种表格、两种图片段、图题、附录标题。生成器只复制原型并替换文字，不定义字体、间距和编号。

标题编号是写在文字里的（“8.1.2.3 ”），不是自动编号。

用户另有验收通过的 docx 并希望沿用它的版式时，把其中对应段落做成同样带标记的模板，用 `--template` 传入。不要在生成器里改版式。

目录页码由 `refresh_toc.py` 调 LibreOffice 刷新。它会改写整个文件，所以必须在生成之后、交付之前运行，并在外层加 `timeout`。

## 物理表卡片

附录 A 需要物理表图片时，为每张表写一份 YAML，用 `render_cards.py <目录>` 渲染成 `images/<id>.png`（需要 `xelatex` 和 `pdftoppm`）。

```yaml
id: db.news_article
title: 新闻文章物理表
tableName: td_news_article
purpose: 保存文章正文、状态和发布信息。
columns:
  - {name: id, type: bigint, label: 主键}
  - {name: title, type: varchar(200), label: 标题}
```

列定义以数据库 DDL 或实体类为准。卡片里不出现计数编号。接口契约不做卡片，也不放进文档。

## 往已有 Word 里补图

用户已经手工改过的 docx 不要重新生成。在其中找到一组现成的“图片段 + 图题段”，复制后替换图片和图题，插到目标位置，再刷新目录。插入前后把文档转成文本比对，确认除新增的图和图题外没有任何变化。
