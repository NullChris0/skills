# 有据中文写作

让每个实质性主张都有相称依据。事实、推断、决策与未知保持各自身份；材料不足时降低承诺，不补造信息。

## Workflow

1. 判断任务属于正式文档还是技术文章。正式文档读取 [formal-docs.md](references/formal-docs.md)，技术笔记或博客读取 [technical-prose.md](references/technical-prose.md)。两类都命中时读取两份。
2. 从用户材料、目标仓库与可用权威来源归集事实、推断、决策和未知。用户只对自身目标、偏好、业务决策和亲历有直接权威；其转述的外部事实仍须核验。
3. 检查每个实质性主张的依据。主动取得适合该主张的权威来源；用户限定材料范围时服从限制。来源冲突时保留冲突及其影响，不自行择优。用户裁决记为决策，不改写成已验证事实。
4. 在动笔前解决会改变文档结构、方案或主要结论的缺口。集中追问会改变结论、范围或行动的问题；能从权威来源查明的先查。关键缺口未解决时不交半稿。若未知本身及其影响可以完整描述，则将它作为文档内容。
5. 新写时采用完成任务所需的最小结构。改稿时只改用户授权的范围，保留作者立场、事实承诺、既定术语与未授权调整的结构。
6. 修订成稿。确认术语一致、信息持续推进、结尾没有超出正文建立的事实、决策、风险、行动或影响。摘要、风险重述和跨章节引用有明确文档功能时可以重复。
7. 默认只交付成稿。只有用户要求审计、评审或说明依据时，才展示主张、来源、冲突与检查过程。来源在内部始终可追溯，对外按用户要求或文档约定呈现；不得泄露内部材料。

## Information boundaries

- 真实案例须有可追溯来源，才可证明问题或需求存在。
- 构造示例须明确标注为示例或假设，并符合已知规则；它只能解释，不能充当证据。
- 同一概念始终使用同一名称。保留代码标识、协议名、产品名和稳定的英文术语；仅在确有歧义时解释，不为中文化强译。
- 写明实际动作的对象、变化或验证方式。专业术语可以保留；无法说明变化的“优化、提升、赋能”等表述需要补实。
- 客户原话、组织术语和用户明确要求保留的措辞不得擅自替换；其含义影响文档时请求确认。

## Expression checks

这些检查按语境修订表达，不把表达问题当作事实错误。

- 删除凭空设置错误观点再推翻以抬高结论的虚构对立。用于消歧、纠错或边界说明的真实对比可以保留。
- 允许边界准确的解释类比；成稿不使用把人的意图、情绪或动作赋予抽象概念的拟人化。
- 让责任主体与实际动作容易定位。只在条件、定语或名词化结构遮蔽主干时重写，不强制口语化或统一语序。
- 删除只宣告重要或深入、却没有增加信息的空路标。成稿不用“说白了”“值得注意的是”“先说结论”。
- 黑话必须落到具体含义。Agent 新写的空泛黑话应改实；引用、既定术语和用户要求保留的措辞不改。
