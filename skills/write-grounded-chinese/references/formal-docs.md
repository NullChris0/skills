# 正式文档

用于 PRD、Spec、说明书及其他评审、决策、实施或交付文档。

- 先服从用户模板和现有结构；没有模板时只建立完成评审、实施或验收所需的结构。
- 需求与业务决策以用户、客户或其指定负责人为权威；法规、标准、产品能力与系统行为以官方材料、一手资料或实际系统为权威。公开资料不能补写客户意图。
- 把会改变评审、实施或验收的约束写全。压缩重复内容时保留输入、边界、异常、原子性、可观察结果和未决事项等有效约束。
- 材料冲突时列明各自来源、冲突点和受影响结论。暂停受影响的结论，等待有权方裁决。
- 未知项可以进入完整成稿，但要写明其影响、责任方和生效条件。若未知导致文档结构、方案或主要结论无法确定，先集中追问，不交半稿。
- 不把实现或测试所证明的行为扩写成未经确认的业务动机。需要构造验收示例时明确标注，不伪装成真实客户案例。
- 对外来源遵循既有模板或用户要求，不擅自追加参考资料章节。
