# 启动访谈

本阶段只确定输入、边界和输出位置。可以只读查看 Agent 规则、领域索引、目录结构和 Git 元数据，以回答能够从项目中查明的事实；不分析功能、不校验 NESMA 条目、不读取业务实现、不生成文件。

## 必需参数

一次调用只处理一个系统。依次补齐会影响后续参数的缺口；可一次请求互不依赖的路径或材料：

1. 系统名称及项目根目录。
2. 该系统全部相关代码仓库，包括前端、后端、脚本或独立数据工程仓库。
3. 每个仓库明确的竣工基线：commit、tag 或交付分支；将 tag 或分支解析为 commit 后固定，不默认采用当前工作区。
4. 项目领域索引及该系统领域文档。由领域文档唯一定位既有 `delivery` 目录；无法定位时阻断，不猜测或创建目录。
5. 正式 NESMA 输入：计数对象与应用边界、详细 FPA 方法、项目类型、清单版本、确认后的未调整功能点总量、与结论对应的功能清单，以及经确认的数据功能 RET/DET 和事务功能 DET/FTR 明细。本 Skill 不接受概要 FPA 或其他不提供这些明细的方法；任一输入缺失或互相无法追溯时阻断。
6. 客户确认材料、既有规格、数据字典、接口材料等补充证据；没有时明确记录为无。
7. 本 session 必需的外部只读访问授权。默认仅使用仓库证据；现网、数据库、浏览器或远程服务只有在仓库证据不足且用户明确授权后才访问。
8. 允许人工补充项的责任人。仅允许封面单位信息、项目背景与往期建设、投资计划金额和界面截图进入成稿占位。

从目标仓库规则中推导事实，不询问能够直接查明的路径、术语或目录。发现输入材料看似属于不同系统、不同版本或不同计数边界时，先说明证据，不代替用户消解。

## 输出版本

输出根目录是领域文档对应的 `delivery` 目录。两份文件均为供用户润色补充的待完善稿，文件名不另加状态标记。两份文件使用同一个 `YYYYMMDD-NN`：日期取本地任务日期，`NN` 是该目录当天已有交付件之后的两位递增序号。现有文件不带版本号时保留原样，不覆盖。

输出文件名：

- `<系统名称>需求说明书-YYYYMMDD-NN.docx`
- `<系统名称>功能清单-YYYYMMDD-NN.xlsx`

## 启动确认

参数齐备后，在单独一轮给出完整摘要：系统与项目、全部仓库及解析后的 commit、领域与 `delivery` 目录、NESMA 方法/项目类型/边界/版本/总量、功能清单及 RET/DET、DET/FTR 明细、补充证据、外部访问范围、允许占位项责任人、待完善稿性质、拟用版本号和两个输出路径。

该轮到此停止。只有用户在后续消息中无条件确认最新完整摘要，才进入证据审查。修正、条件或范围变化使之前确认失效；更新参数后重新给出完整摘要并等待确认。

启动取消或未确认时不创建目录、不复制模板、不生成交付件。
