# 成稿与校验

只有证据审查通过后执行本阶段。写入前复核输入校验值和固定 commit；任一变化返回证据审查。成稿时读取 [结构示例.md](结构示例.md)，只学习组织方法，示例不证明目标系统存在相应功能。

## 输出与模板

在已确认的 delivery 目录创建同版本的两份独立 TeX 源文件。目标文件已存在时阻断，不覆盖旧版本。两份内置联通空白模板仅作为章节和字段参考，默认不填充或生成 Word、Excel 文件。

客户明确指定的章节、列名及顺序优先。没有额外要求时，说明书沿用项目概述、文档目的、文档范围、术语、参考文档、范围定义、功能需求的主干；第 7 章组织数据模型与业务功能，接口契约随功能呈现，后续为界面需求、非功能性需求及适用的其他需求。无需保留空的独立接口章。模板占位与其他项目示例只提供结构，成稿替换为本系统内容。

### TeX 约定

使用支持中文的文档类和简洁的表格、图示表达。每份文件包含完整导言区与文档环境，声明所用宏包，简要注明预期编译引擎；功能清单可用横向页面、跨页表格和合并单元格。图片采用随交付可定位的相对路径，引用与标签保持一致。优先将文字写入源文件，不引入额外生成脚本或复杂工具链。

默认只检查源文件，不执行编译或转换。用户明确要求 PDF 时才编译并检查渲染；要求 Excel 时，从功能清单内容转换并保留列、顺序、合并关系与计量身份。TeX 不是 Excel 的原生输入，不把转换描述为编译步骤。工具不可用时报告缺口，不声称派生文件已生成。

## 需求说明书

以竣工态描述系统对外可观察的业务约束，完整覆盖重写后系统的已交付能力。项目概述、目的、范围、术语和参考文档采用证据支持的内容；系统总体功能结构包含有依据的功能结构图。

“本项目预算工作量”集中说明已确认的 NESMA 对象、边界、详细 FPA 方法、项目类型、清单版本、数据与事务功能数量及未调整功能点总量。逐项计量编号、类型和复杂度明细留在功能清单与 NESMA 材料，正文无需展示“对应功能清单序号”。“投资计划预算”只使用有权来源提供的金额或允许占位，不自行将功能点换算为金额。

### 数据模型

第 7.1 章按业务域组织用户可理解的数据模型，每个模型采用以下结构：

- **需求描述**：业务身份、数据分组、关键字段及其定义、约束，适用的生命周期和消费方。
- **数据来源及流向**：数据从哪里产生，进入哪些页面、功能、接口或后台过程；外部来源使用真实名称。
- **加工逻辑**：创建、维护、计算、同步、冻结、终止、归档或删除等实际发生的处理及更新触发。

业务模型与物理表、NESMA 数据功能分别建立映射，不按物理表或计量编号机械拆章。正式 RET、DET 的业务含义应得到覆盖，但正文无需照抄计量详表，也不强制用 RET/DET 表格表达。跨模型同名字段须保留其业务身份与归属。

业务模型之后可集中补充物理表结构，说明模型与表的对应关系，列真实表名、字段名、SQL 类型、必填和约束。物理结构补充业务模型，不以表数或字段数推导功能点。复杂数据流用图示表达。

### 页面与后台业务功能

第 7.2 章按页面、工作台或共同用户任务分组。页面级集中写入口、角色、共同数据、状态、权限、交互和共用截图；叶子功能写特有的主体、触发、输入、处理规则及结果，权限与异常按实际差异补充，随后给出相关接口契约。同一页面共同信息只写一次。

确无界面入口的批处理、文件处理等业务能力归入适用的后台业务功能章节。跨系统读取可按调用场景组织。跨页面、跨角色或复杂状态流程用业务流程图或状态图，简单功能无需配图。

业务能力、接口契约与计量条目按各自粒度组织。一个基本过程可由多个接口实现；未独立计数但确已交付的能力仍正常描述，其计量归属或排除理由留在功能清单与内部映射。正文层级不强制与计量行一对一，拆分或合并展示均须保留完整映射和不重复计量的依据。

### 随功能呈现的接口契约

覆盖接口台账中的全部业务应用接口与跨系统接口，在所属功能下面呈现。共享契约只写一次，其他功能引用同一标签；客户指定独立接口章时移入该章并保留功能引用。

接口表交代名称、类型、方向、调用方与被调用方、业务输入输出、校验约束及错误规则。同步调用补充协议、地址或服务、操作或方法、权限、会话、数据范围及事务规则；异步文件、消息、交换表或批处理补充载体、格式、触发与频率、确认、重试、幂等及异常处理。

允许真实字段名及必要的协议信封。字段表承担契约说明；嵌套、集合或返回结构需要示例才能清楚时，可附精简的完整 JSON 示例，使用构造数据并与契约一致。无需为每项接口重复通用响应包装，不把 Java 内部调用、框架接口、无业务含义的技术端点或本机路径列为业务接口。

### 界面、非功能与支撑工作

界面需求章描述跨页面且可观察、可验收的 UI/UX 行为；截图放在对应页面章节。非功能性需求独立说明，响应时间、并发、超时、文件大小等数值须来自合同、配置、测试或用户确认，不从终稿示例继承。

数据来源、加工、接口、异常与原子性等实际工作内容进入相应章节。迁移、清洗、定时任务、权限改造等工作按实际业务身份和正式计量归属描述；未纳入功能点的支撑工作进入建设范围或对应支撑能力，保留处理规模与结果依据。

允许待补项仅为封面单位信息、项目背景与往期建设、投资计划金额和界面截图，使用 `【待补：责任人—内容】`；其他影响范围、计量或验收的未知返回审查。

## 功能清单

以独立 TeX 表格承载联通功能清单，保持列：序号、系统名称、一级模块、二级模块、功能需求描述、外部接口需求描述、功能（新增/修改）、备注。连续行的系统名称或共同模块可合并单元格，每行功能与计量身份仍须可独立追溯。

- 保持已确认清单的计量边界、顺序与身份，按竣工证据完善文字。分组名称与正文对应的业务域或页面一致；名称不同但业务映射明确时无需强制标题相同。
- 正式计量条目各出现一次，备注保留 NESMA 编号和类型。一个计量行可映射多个正文位置，一个正文功能可实现多个计量条目，内部映射列明关系及基本过程边界。
- 未独立计数的能力与支撑工作沿用正式输入的归属或排除项；需要补充展示时单列并注明“未独立计数”及原因，不新增计量编号、不纳入总量。归属或排除理由未确认则返回审查。
- 系统、功能、行为、接口方向、新增/修改口径与正文一致。模块共同背景不在每行重复。
- 需要改变 NESMA 总量、功能边界、类型或详表时停止成稿，列明需要修正的输入并返回审查。

## 完成校验

重新读取两份源文件，逐项检查：

1. 两份文件完整、同版本、未覆盖旧文件；各自的文档环境、宏包、命令、表格列数、合并关系、引用标签和资源路径自洽，TeX 特殊字符已正确处理。
2. 正文层级与已确认的客户要求一致；业务模型、页面和叶子功能可识别，共同信息及截图没有重复铺陈。
3. 正式计量条目、实际业务能力和业务接口分别全覆盖，正文与功能清单的映射完整，计量行没有重复。多入口、共享接口、未独立计数能力均保留正确归属。
4. 数据模型的业务含义、来源流向、加工更新、适用生命周期与消费方齐备；正式 RET、DET 的业务含义无遗漏或无依据合并，物理表没有替代业务模型。
5. 接口契约均有唯一说明位置和有效引用，输入、输出、规则及适用传输约定与证据一致；正文与清单的系统名称、行为、接口方向及新增/修改口径一致。
6. 功能结构图与必要流程图齐备，截图或允许占位位于对应页面；界面与非功能要求可验收，数值有来源。
7. NESMA 对象、边界、方法、项目类型、版本、条目数量及总量与已复核输入一致。模板项目事实、未支持的需求和指标没有进入文档。
8. 仅保留允许待补项，并汇总数量和位置。

检查失败时修正受影响内容并重新核对关联映射；若涉及事实或计量基线，返回审查。默认不以编译作为完成条件，也不声称源文件已通过编译或版面检查。用户要求派生格式时，再校验其实际渲染或转换结果。

完成后报告两份源文件的绝对路径、版本、NESMA 总量、允许待补项及验证范围。只交付约定源文件、必需图像资源及用户要求的派生文件；不另建审计报告或中间稿，不声称文件已经可以直接提交客户。
