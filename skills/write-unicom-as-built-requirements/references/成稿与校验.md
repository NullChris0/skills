# 成稿与校验

## 输入

唯一计数输入是阶段一 JSON。旧 Word/PDF、旧功能清单和旧 `api-tables` 不得提供 NESMA 编号、类型、FP 或业务事实。它们只能在用户明确要求时帮助理解版式。

## 映射表

先建立 `映射表.xlsx`，至少包含：

- NESMA 编号、类型、名称、FP；
- 功能清单序号和功能名称；
- 正文章节、页面或数据模型位置；
- 接口 YAML 或卡片 ID；
- 覆盖状态和说明。

每条 NESMA 记录必须有归属；一个功能清单行可以映射多个 NESMA 记录，一个 NESMA 记录可以出现在正文多个位置。不得重复计量。

## 功能清单

使用 `assets/联通功能清单模板.xlsx` 的列顺序：

序号、系统名称、一级模块、二级模块、功能需求描述、外部接口需求描述、功能（新增/修改）、备注。

功能清单按用户可理解的业务功能组织。备注保留正式 NESMA 编号；未独立计数的能力写明“未独立计数”和已确认的归属或排除理由，不新增编号。连续行的系统名称和共同模块可合并单元格，但不得跨页。

## 接口表

按 [接口表YAML规范.md](接口表YAML规范.md) 生成 YAML。YAML 是编辑面，TeX 卡片和图片是投影：

```text
YAML -> TeX 卡片 -> PNG/SVG 图片 -> Word
```

Word 中为每张接口表保留图位、图题、表号和正文引用。接口表只描述成功契约和代码基线支持的字段，不复制旧交付件中的错误码、示例或路径。

## Word

Word 直接生成，不用 PDF 转 Word。建议章节：

1. 项目概述
2. 文档目的
3. 文档范围
4. 术语和缩写
5. 参考文档
6. 范围定义
7. 数据模型
8. 页面与业务功能
9. 接口需求（只放总述和接口图片引用）
10. 界面与非功能需求

数据模型按业务身份组织，物理表作为补充，不按表数推导数据功能。页面按入口、角色、共同数据、状态和叶子功能组织；接口契约随所属功能呈现。

## 完成校验

```bash
python <skill-directory>/scripts/build_delivery.py <delivery-model.json> <输出目录>
python <skill-directory>/scripts/validate_delivery.py <计数模型.json> <输出目录>
```

- JSON 的每个数据功能、事务功能都在映射表中有唯一归属；
- 功能清单没有旧编号、旧 UFP 或未确认假设；
- 接口 YAML 的端点、方法、鉴权和字段有代码证据；
- 每张 YAML 卡片有对应图片，Word 中图片可打开且图题/引用连续；
- Word 中的数据功能数、事务功能数和 UFP 完全来自 JSON，不写死；
- Word 中出现的全部 `N UFP` 必须等于计数模型复算值，全部 DF/TF 编号必须存在于计数模型；
- 数据割接、迁移、环境切换等非计数工作未进入 FP；
- 输出目录只包含本次版本产物，不覆盖旧版本。
