# 证据审查与阻断

本阶段只读审查，不创建或修改交付件。先记录全部输入文件的稳定定位与校验值，并固定每个仓库解析后的竣工 commit；审查结束前输入变化使本轮结论失效。

## 取证范围

1. 读取每个目标仓库适用的 `AGENTS.md`，以及项目领域索引、目标领域 `CONTEXT.md` 和相关 ADR。查找或解释 tag 时同时遵守项目 Git 导航规则。
2. 从固定 commit 检查目标领域相关的前端页面与路由、后端入口与业务服务、权限、配置、数据模型、SQL、接口、批处理和测试。当前工作区只用于读取规则与领域文档，不作为竣工行为证据。
3. Git 历史只用于解释交付来源、定位重写范围或解决证据断点；竣工 commit 的实际行为决定成稿事实。
4. 模板和兄弟厂商样例只决定章节与表达方式，不能证明本系统存在某项需求、业务动机或非功能指标。
5. 默认不访问现网、数据库、浏览器和远程服务。仓库证据不足以判定关键功能时，登记缺口并暂停申请当前 session 的明确只读授权。

## 双向覆盖

建立临时映射，不写入仓库：

- 清单到系统：功能清单每一行都须在竣工 commit 中找到可定位证据，且行为、用户、输入、处理和输出与描述一致。
- 系统到清单：竣工 commit 中每项可识别的已交付业务能力都须回到一行功能清单。不能因为清单未列而忽略已完成工作。

分别覆盖计量条目、已交付业务能力和业务接口，建立它们到正文位置的映射，不强制正文标题与计量行一对一。一个基本过程可由多个接口实现，共享接口可服务多个能力；拆分展示不产生新计量条目，合并展示仍须覆盖各条目的独立业务含义。未独立计数的能力保留正式输入中的归属或排除理由，归属不明时阻断并列明缺口。

数据迁移、清洗、定时任务、权限改造等支撑工作可以独立登记工作内容、处理规模和结果；除非正式 NESMA 结论已经纳入，否则不得伪装成功能点或改变总量。

同时核对：

- 系统名称、领域、仓库与竣工版本属于同一交付对象；
- NESMA 对象、应用边界、方法、项目类型、清单版本和未调整功能点总量互相一致；
- 接口方向、数据来源与流向、权限边界、关键业务规则、异常与原子性能够由证据支持；
- 非功能指标有合同、配置、测试或运行证据；
- 已交付全量能力已覆盖，而不只是相对老系统的差异。

## 成稿台账

双向覆盖完成后建立四份临时台账，不写入仓库：

- **数据模型台账**：独立于 NESMA 清单识别业务数据模型及其分组，记录目的、数据定义与约束、来源、加工更新、生命周期、消费方及证据定位。分别映射物理表与正式数据功能，保留 RET、DET 的业务身份和原计量归属；同名不自动合并。正文可按业务身份分组，但计量详表不得因此改变，表数也不决定数据功能数量。
- **页面台账**：按页面、工作台及页签记录入口、角色、共同数据、状态、权限、业务能力、计量归属、正文位置和共用截图。跨页面基本过程保留各页面的参与关系，不因此重复计数；确无界面入口的能力归入后台业务功能。未独立计数的能力同样登记。
- **接口台账**：登记全部业务应用接口和跨系统接口，记录名称、类型、方向、调用方与被调用方、业务输入输出、约束校验、错误规则、计量归属及证据定位。同步调用另记协议、地址或服务、操作或方法、权限或会话及事务规则；异步交换另记载体、格式、触发频率、确认、重试、幂等和异常处理。每项契约确定一个说明位置，记录全部消费功能的引用；多入口与共享接口均保留各自映射。排除内部调用、框架接口及无业务含义的端点；接口数量不作为功能点数量。
- **图示台账**：整理系统功能结构，并标识需要流程图或状态图才能清楚表达的跨页面、跨角色或复杂状态流程。界面截图沿用页面台账的共用关系。

四份台账必须分别与竣工证据和正式功能清单闭合：每个模型有实际消费方和已确认的计量归属，每个正式数据功能及其详表得到覆盖，每个事务功能有页面或后台归属，每项实际能力有计量归属或排除理由，每个业务接口有消费功能且涉及接口的功能能回到契约，图示节点与连线均有证据。覆盖关系可为多对多，但正式计量条目不重复。

## 阻断条件

以下任一项成立时阻断：

- 系统、仓库、领域、竣工 commit、`delivery` 目录或 NESMA 输入身份不清；
- NESMA 条目与实现行为冲突，或双向覆盖不闭合；
- 关键功能、业务规则、接口、数据流、范围或非功能指标缺少足以成稿的证据；
- 客户材料之间存在会改变范围、计量或验收结论的冲突；
- 输入在审查期间变化；
- 除允许占位项外仍有未知会进入正式文档。

发现首个问题后停止成稿准备，但继续完成能够安全进行的本轮只读一致性审查。随后一次列出全部已发现问题，每项包含：材料与具体定位、相互冲突或缺失的事实、受影响的功能序号/范围/计量/验收结论、需要用户或有权来源修正的内容。

该轮不写半稿。若修正改变系统、范围、基线、NESMA 结论或输出位置，返回启动访谈重新确认；其他修正重新执行完整证据审查。

缺少已复核结论或发现计量不一致时，汇总计数对象、固定版本、现有清单与详表、问题定位、观察行为及受影响条目。先排除不同版本造成的表面差异，不根据接口数量、物理字段数量或响应示例直接推导功能点变化。等待补充或修正后的已复核输入，再按上述规则重新确认与审查。

## 通过条件

只有双向覆盖闭合、四份成稿台账完整、全部实质主张都有相称证据、NESMA 输入完整一致且阻断清单为空，本阶段才完成。记录输入校验值、功能映射、成稿台账和允许占位项，随后读取成稿指令。
